# Предварительная версия CUSTOS для рабочего стола Linux

[English](README.md)

Предварительная версия добавляет графическое окно к службе резервного копирования CUSTOS для Linux. Служба
выполняет задания по расписанию при закрытом окне. Для локальных копий подключение к Monitor необязательно.

## Скачивание и установка

Откройте **Assets** в [выпуске на GitHub](https://github.com/openpass1/custos/releases), в котором есть версия для
рабочего стола Linux. Выберите пакет для своего дистрибутива и процессора. Для службы нужен systemd, для окна — X11.
В сеансе Wayland нужен XWayland.

| Дистрибутив | 64-разрядные Intel или AMD | 64-разрядный ARM |
| --- | --- | --- |
| Debian 12/13, Ubuntu 22.04/24.04/26.04 и совместимые версии Linux Mint | `custos-desktop_<версия>_amd64.deb` | `custos-desktop_<версия>_arm64.deb` |
| Fedora 44 | `custos-desktop-<версия>-1.x86_64.rpm` | `custos-desktop-<версия>-1.aarch64.rpm` |

Чтобы скачать сборку для тестирования, войдите в GitHub и откройте успешный
[запуск Linux desktop preview](https://github.com/openpass1/custos/actions/workflows/linux-desktop-preview.yml)
для нужной версии. В разделе **Artifacts** скачайте `custos-linux-desktop-preview-deb-amd64` или
`custos-linux-desktop-preview-deb-arm64` для систем на базе Debian, `custos-linux-desktop-preview-rpm-x86_64` или
`custos-linux-desktop-preview-rpm-aarch64` для Fedora. Извлеките пакет из ZIP.

Откройте пакет в программе установки пакетов и нажмите **Установить**. Из терминала выполните команду для своего
дистрибутива в папке с пакетом, подставив имя скачанного файла.

```sh
sudo apt install ./имя-файла.deb  # Debian, Ubuntu, Linux Mint
sudo dnf install ./имя-файла.rpm  # Fedora
```

Откройте **CUSTOS** из меню приложений под своей учётной записью. При первой установке пакет запускает службу
резервного копирования. В live-сеансе без сохранения изменений пакет и настройки доступны до перезагрузки.

Чтобы изменить язык окна, выберите **Настройки → Язык интерфейса** и снова откройте CUSTOS. Панель рабочего
стола с поддержкой трея может показывать значок CUSTOS, пока окно открыто.

## Обновление и удаление пакета

Установите более новый пакет того же формата, чтобы обновить окно и агент из пакета. Если агент ранее установили
через Monitor, окно подключится к существующей службе. Monitor сможет обновлять эту службу отдельно. Для всех
возможностей окна используйте ту же версию агента. В системах на базе Debian пакет `custos-desktop` заменяет
прежний `custos-desktop-preview` и сохраняет его данные. Первая установка пакета с новым именем включает автозапуск
службы. Чтобы она осталась остановленной при переходе, сначала выполните `sudo systemctl mask --now custos.service`.

Чтобы удалить пакет, выполните `sudo apt remove custos-desktop` или `sudo dnf remove custos-desktop`. Задания,
настройки, история запусков и сделанные копии сохраняются.

Если вы запускали `add-menu-entry.sh` из отдельного архива, удалите созданный им ярлык из
`${XDG_DATA_HOME:-$HOME/.local/share}/applications`, чтобы меню открывало установленную версию.

## Первое задание резервного копирования

1. Откройте CUSTOS под учётной записью администратора Linux из группы `sudo` или `wheel` и нажмите **Создать**.
2. Введите название. В **Источниках** добавьте папку с файлами. В **Назначениях** выберите отдельную папку для
   копий, за пределами источника.
3. Нажмите **Сохранить**, выберите задание в главном окне и нажмите **Запустить**. Проверьте результат в
   **Истории запусков**.

По умолчанию новое задание Linux запрашивает снимок файловой системы. Если снимок недоступен, как в некоторых
live-ВМ, агент продолжает копирование с предупреждением. Если снимок обязателен, включите остановку задания при
ошибке в разделе **Дополнительно**.

## Управление заданиями

Выберите задание, чтобы изменить, клонировать, включить, отключить или удалить его. Копия задания создаётся
отключённой. В меню рядом с кнопкой **Создать** есть импорт и экспорт файлов заданий CUSTOS. Для экспорта
нужна учётная запись администратора Linux. Если пути в импортированном задании несовместимы с Linux, CUSTOS
сохранит их для редактирования, а задание отключит.

В разделе **Настройки → Все настройки…** можно изменить параметры службы, в том числе права доступа, срок
хранения журналов и пароль программы. Язык журналов службы настраивается отдельно.

## Подключение к CUSTOS Monitor

В CUSTOS откройте **Настройки → Сервер мониторинга**. Скопируйте строку подключения со страницы **Установка** в
Monitor, вставьте её в поле подключения и нажмите **Подключить**. В Monitor 1.4.2 строка находится в разделе
**Windows и macOS**. После регистрации сравните отпечаток ключа в CUSTOS с отпечатком в Monitor и подтвердите машину
в разделе **Машины**.

## Восстановление файлов

Нажмите **Восстановить**, выберите задание, папку с копиями, сервер или облачное хранилище и нажмите **Найти копии**.
Выберите дату и папку для восстановления, затем ещё раз нажмите **Восстановить**. По умолчанию существующие файлы
пропускаются. Если копия зашифрована и служба не знает её пароль, введите пароль архива. Для восстановления нужна
учётная запись администратора Linux.

## Подключение облачного диска

Под учётной записью администратора Linux откройте **Настройки → Все настройки…** и найдите **Учётные записи сетевых
папок, серверов и облачных дисков**. Выберите Google Диск, Яндекс Диск или Dropbox и откройте страницу входа в
браузере. Google Диск отправит ответ в CUSTOS. Для Яндекс Диска или Dropbox вставьте показанный в браузере код в
окно CUSTOS. Выберите подключённую учётную запись в **Назначениях** задания.

Если в сборке нет встроенного приложения для сервиса, зарегистрируйте своё и добавьте его в разделе
**Облачные диски → Свои приложения…**.
[Форматы копий и шаги подключения](../../README.ru.md#облачные-диски-google-drive-яндекс-диск-dropbox)

## Архив только с графическим окном

Если агент Linux уже установлен, скачайте `custos-linux-desktop-<версия>-x64.tar.gz` или
`custos-linux-desktop-<версия>-arm64.tar.gz` из выпуска с версией для рабочего стола. Для сборки из корня
репозитория нужны .NET 10 SDK и GNU `tar`. Укажите нужную версию и при необходимости замените `x64` на `arm64`.

```sh
version=1.5.0
bash client/linux/build-desktop.sh x64 client/artifacts-linux/desktop "$version"
tar -xzf "client/artifacts-linux/desktop/custos-linux-desktop-$version-x64.tar.gz"
"./custos-linux-desktop-$version-x64/custos-gui"
```

В архив входит среда выполнения .NET. Программа использует системные glibc, ICU и графические библиотеки.
Установите [агент резервного копирования Linux](../../README.ru.md#custos-для-linux) отдельно. Запускайте окно от
своего пользователя и храните распакованные файлы вместе. Окно подключается к агенту через `/var/run/custos.sock` и
соблюдает его правила доступа. Если у тестового агента другой сокет, перед запуском окна задайте его доверенный
абсолютный путь в `CUSTOS_SOCKET`.

Для проверки окна без агента запустите `custos-gui --demo` с демонстрационными данными.

Чтобы добавить ярлык в меню приложений, запустите `./add-menu-entry.sh` из распакованной папки. Ярлык доступен
вашему пользователю и указывает на эту папку. При переносе папки запустите скрипт снова. Для удаления ярлыка
удалите `org.custos.Desktop.desktop` из `${XDG_DATA_HOME:-$HOME/.local/share}/applications`. В ранних сборках для
тестирования файл назывался `org.custos.DesktopPreview.desktop`.

Скрипт принимает архитектуру, папку результатов и версию. По умолчанию используются `x64`,
`client/artifacts-linux/desktop` и верхняя версия из [списка изменений клиента](../../CHANGELOG.md).
Иконка PNG размером 256 пикселей взята из `client/src/Custos.Desktop/Assets/custos.ico`.

## Сборка пакетов для выпуска

На GitHub откройте **Actions → Release → Run workflow**, выберите `client` и введите верхнюю версию из списка
изменений клиента. Параметр `linux` включает архивы агента и ZIP обновления для Monitor. Оставьте `linux_desktop`,
чтобы добавить `.deb`, `.rpm` и отдельный архив с окном. Снимите эту отметку, чтобы выпустить только Linux-агент.
Перед публикацией проверьте черновик выпуска и `SHA256SUMS.txt`.

## Проверки совместимости

| Среда | Проверка |
| --- | --- |
| Debian 13 amd64, Wayland (Weston 14.0.2 и XWayland 24.1.6) | При обновлении с предварительной версии 1.4 сохранились данные и автозапуск службы. Окно 1.5.0 открылось из установленного ярлыка и подключилось к службе под обычной учётной записью. |
| Ubuntu 24.04, x64 и ARM64 | Процесс **Linux desktop preview** проверяет установку, переустановку и удаление `.deb`, а также совместимость с уже установленным агентом. |
| Контейнер Fedora 44, x86_64 и aarch64 | Процесс проверяет установку RPM, ярлык, исполняемые файлы и удаление пакета. |
