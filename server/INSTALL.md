# Установка CUSTOS Monitor на CloudPanel, пошагово

English version: [INSTALL.en.md](INSTALL.en.md). Установка на сервер без CloudPanel (обычный nginx) описана в разделе [«Без CloudPanel»](#без-cloudpanel) в конце.

Делайте шаги по порядку. После каждого шага написано, что должно получиться. Если получилось не так, смотрите раздел «Если что-то пошло не так» в конце.

В примерах используются такие имена. Если выбрали другие, подставляйте свои везде:

| Что | В примерах |
|---|---|
| Адрес сайта | `custos.lan` |
| Версия PHP сайта | 8.4, поэтому в командах `php8.4`. Если в CloudPanel выбрана 8.5, пишите `php8.5` |
| Пользователь сайта в CloudPanel | `custos` |
| База данных | `custos` |
| Пользователь базы данных | `custos` |

Два правила:

- Все команды в SSH выполняются **под пользователем сайта** (`custos`), не под root.
- PHP-скрипты запускаются только так: `php8.4 bin/install.php`. Если не написать `php8.4` в начале, будет ошибка `Permission denied` или `?php: No such file or directory`. `chmod` делать не нужно.

## Часть 1. Скачать пакет (на своём компьютере)

**Шаг 1.** Откройте репозиторий на GitHub. Перейдите в **Actions**, слева выберите **Server**. Откройте верхний запуск с зелёной галочкой. Внизу страницы, в блоке **Artifacts**, нажмите `custos-server`.

✅ Скачался файл `custos-server.zip`. Распаковывать его на компьютере не нужно.

> Пакет хранится 14 дней. Если в блоке Artifacts пусто, на странице **Actions → Server** нажмите **Run workflow**, подождите пару минут и откройте новый запуск.

---

## Часть 2. CloudPanel (в браузере)

**Шаг 2. Сайт.** **Sites → + Add Site → Create a PHP Site**. Заполните:

- Application: **Generic**
- Domain Name: `custos.lan`
- PHP Version: **8.4** или новее
- Site User: `custos`, Site User Password: придумайте и запишите (понадобится для SSH)

Нажмите **Create**.

✅ Сайт появился в списке сайтов.

**Шаг 3. Корневая папка.** Откройте сайт, вкладка **Settings**. В поле **Root Directory** вместо `custos.lan` впишите `custos.lan/server/public`. Нажмите **Save**.

**Шаг 4. База данных.** В сайте вкладка **Databases → Add Database**:

- Database Name: `custos`
- Database User Name: `custos`
- Database User Password: придумайте и запишите (понадобится в шаге 10)

✅ База появилась в списке.

**Шаг 5. Только если сайт будет работать по HTTP (без сертификата).** В сайте вкладка **Vhost**. Найдите такой блок и удалите его целиком, затем **Save**:

```nginx
if ($scheme != "https") {
  rewrite ^ https://$host$request_uri permanent;
}
```

Если такого блока нет, ничего не делайте. С этим блоком агенты по HTTP работать не смогут.

## Часть 3. Загрузить пакет на сервер

**Шаг 6.** В сайте вкладка **File Manager**. Откройте папку `custos.lan` и загрузите туда `custos-server.zip` (кнопка **Upload**).

Можно и через WinSCP: протокол SFTP, логин `custos` и пароль из шага 2, папка `/home/custos/htdocs/custos.lan/`.

✅ В папке `custos.lan` лежит `custos-server.zip`.

## Часть 4. Установка по SSH

**Шаг 7. Войти на сервер под пользователем сайта.** На своём компьютере (PowerShell или PuTTY):

```bash
ssh custos@адрес-сервера
```

Пароль: из шага 2. Затем проверьте, кто вы:

```bash
whoami
```

✅ Выводится `custos`. Если выводится `root`, выйдите (`exit`) и войдите как `custos`.

**Шаг 8. Распаковать пакет.**

```bash
cd ~/htdocs/custos.lan
unzip -o custos-server.zip
rm custos-server.zip
cd server
ls
```

✅ `ls` показывает: `INSTALL.en.md INSTALL.md README.md bin composer.json composer.lock config lang migrations public src templates tools vendor zabbix`.

С этого места все команды выполняются из папки `~/htdocs/custos.lan/server`.

**Шаг 9. Создать файл настроек.**

```bash
cp config/config.example.php config/config.php
```

Команда ничего не выводит, это нормально.

**Шаг 10. Заполнить настройки.**

```bash
nano config/config.php
```

Поменяйте значения в этих строках (кавычки оставьте):

```php
        'name' => 'custos',          // имя базы из шага 4
        'user' => 'custos',          // пользователь базы из шага 4
        'password' => 'change-me',   // ← пароль базы из шага 4
...
    'url' => 'http://custos.lan',    // ← адрес сайта, как его открывают в браузере, с http:// или https://
...
    'timezone' => 'UTC',             // ← ваш часовой пояс, например 'Europe/Berlin'
```

Сохранить: **Ctrl+O**, затем **Enter**. Выйти: **Ctrl+X**.

**Шаг 11. Запустить установку.**

```bash
php8.4 bin/install.php
```

Скрипт задаст три вопроса:

1. `Login of the first administrator:` — логин для входа на сайт, например `admin`.
2. `Password (at least 8 characters):` — пароль, не короче 8 символов. При вводе он не отображается, это нормально.
3. `Repeat the password:` — тот же пароль ещё раз.

✅ Должно получиться так (код и отпечаток у вас будут свои):

```
[ok] PHP 8.4.x with all required extensions
[ok] Database 10.11.x-MariaDB
[ok] Applied migration 001_init.sql
...
[ok] Applied migration 004_analytics.sql
[ok] Folder /home/custos/htdocs/custos.lan/server/var is ready
[ok] Created the server key pair in /home/custos/htdocs/custos.lan/server/config/keys
Login of the first administrator: admin
Password (at least 8 characters):
Repeat the password:
[ok] Created administrator "admin"
[ok] Generated the agent registration key
[ok] Generated zabbix_token
[ok] Generated wall_token

Server key fingerprint:  XXXX-XXXX-XXXX-XXXX
Connection string:       http://custos.lan#XXXXX-XXXXX-XXXXX-XXXXX-XXXXX#XXXX-XXXX-XXXX-XXXX
It is also shown on the site under Settings.

Add a cron job that runs every minute:
  * * * * * /usr/bin/php8.4 /home/custos/htdocs/custos.lan/server/bin/cron.php
```

Все строки начинаются с `[ok]`. **Connection string** — строка подключения: адрес сервера и код регистрации вместе. Её вставляют в программе CUSTOS на машине. Записывать её не обязательно: она всегда есть на сайте в разделе «Настройки».

Если какая-то строка начинается с `[error]`, исправьте то, что в ней написано, и запустите `php8.4 bin/install.php` ещё раз. Повторный запуск ничего не ломает.

**Шаг 12.** В сайте вкладка **Cron Jobs → Add Cron Job**:

- Name: `custos`
- Расписание: каждую минуту (все поля `*`)
- Command:
  ```
  /usr/bin/php8.4 /home/custos/htdocs/custos.lan/server/bin/cron.php
  ```

Нажмите **Add Cron Job**.

## Часть 6. Проверить сайт

**Шаг 13.** В браузере откройте `http://custos.lan`.

✅ Открывается страница входа CUSTOS. Во вкладке браузера виден значок-щит CUSTOS. Войдите с логином и паролем из шага 11. Видна «Главная»: плитки «Машины 0 / 0», блок «Требует внимания» с надписью «Проблем нет.» и ниже «Результаты за 30 дней» с надписью «Подтверждённых машин пока нет.».

Язык (русский или английский), тему (светлая, тёмная или как в системе) и свой пароль каждый пользователь меняет сам: щёлкните свой логин справа вверху.

Если в блоке «Требует внимания» красная надпись про cron, подождите минуту и обновите страницу. Надпись осталась — cron из шага 12 не работает: проверьте путь к `cron.php` и версию PHP в команде.

## Часть 7. Проверить работу с агентом (имитатор)

Имитатор ведёт себя как настоящий агент: регистрируется, присылает задания и запуски. Команды выполняются по SSH, как в части 4, из папки `~/htdocs/custos.lan/server`.

**Шаг 14.** Возьмите строку подключения на сайте: «Настройки», поле «Строка подключения», кнопка «Скопировать». Вставьте её в команду между одинарными кавычками:

```bash
php8.4 tools/fake-agent.php --connect='СЮДА-СТРОКУ' --once
```

✅ Последние строки вывода:

```
FAKE-PC-01: waiting for approval on the site (key fingerprint XXXX-XXXX-XXXX-XXXX); 3 report(s) kept in the outbox
done: every answer was signed and accepted
```

**Шаг 15.** На сайте обновите страницу «Машины». В блоке «Ждут подтверждения» появилась `FAKE-PC-01`, отпечаток ключа совпадает с выводом. Нажмите **Подтвердить**.

**Шаг 16.** Запустите имитатор ещё раз. Код уже не нужен, только адрес сайта:

```bash
php8.4 tools/fake-agent.php --url=http://custos.lan --once
```

✅ В конце снова `done: every answer was signed and accepted`. На сайте у машины `FAKE-PC-01` появились 4 задания, а в «Запусках» — запуски с журналами. На странице «Машины» задания показаны цветными метками: зелёная — в норме, жёлтая — с предупреждениями, красная — ошибка. Если имитатор выбрал результат «ошибка», на «Главной» в блоке «Требует внимания» появится эта ошибка.

На странице машины появился блок «Хранилища»: куда пишут задания, сколько там свободно и какие наборы копий лежат. Прогноз заполнения появится, когда наберутся данные хотя бы за сутки. Если до заполнения останется 14 дней или меньше (порог в «Настройки» → «Пороги»), на «Главной» появится проблема «место» и придёт одно сообщение. Запустите имитатор ещё раз той же командой: на странице первого задания появятся графики (размер источника, записано, длительность), а на «Главной» в тепловой карте — цветная клетка за сегодня.

**Шаг 17. Убрать тестовую машину.**

```bash
php8.4 tools/fake-agent.php --reset
```

На сайте откройте машину `FAKE-PC-01` и нажмите **Удалить**.

Установка закончена.

## Часть 8. До подключения настоящих агентов

Агенты присылают журналы до 8 МБ, поэтому nginx и PHP должны пропускать запросы до 10 МБ. Имитатору это не нужно, поэтому шаг можно сделать позже.

**Шаг 18. PHP.** В сайте вкладка **Settings**, блок **PHP Settings**: значение `post_max_size` не меньше `10M` (обычно там уже больше).

**Шаг 19. nginx.** Эта команда выполняется **под root**:

```bash
nginx -T 2>/dev/null | grep client_max_body_size
```

✅ Значение не меньше `10m` (например `client_max_body_size 64m;`). Если команда ничего не вывела, у nginx лимит 1 МБ: в сайте вкладка **Vhost**, внутри блока `server { ... }` добавьте строку `client_max_body_size 100m;` и нажмите **Save** (агентам хватает 10 МБ, больше нужно для загрузки пакетов обновления через сайт).

## Часть 9. Уведомления в Telegram и на почту (по желанию)

Сообщения приходят только о проблемах: задание закончилось ошибкой или пропустило запуск, когда машина была включена. Одно сообщение на проблему, без повторов.

**Telegram.**

1. В Telegram напишите боту `@BotFather` команду `/newbot`, придумайте имя. Он пришлёт токен вида `123456789:AA...`.
2. Добавьте своего бота в группу, куда должны приходить сообщения, и напишите в группе любое сообщение. Для личных сообщений просто напишите боту `/start`.
3. Узнайте Chat ID. Откройте в браузере (вместо `ТОКЕН` вставьте токен из пункта 1):
   ```
   https://api.telegram.org/botТОКЕН/getUpdates
   ```
   Найдите `"chat":{"id":-100...`. Число вместе с минусом и есть Chat ID. У группы оно начинается с `-100`, у личного чата — без минуса. Если там пусто (`"result":[]`), напишите в группу ещё одно сообщение и обновите страницу.
4. На сайте: «Настройки» → вкладка «Telegram и почта». Вставьте токен и Chat ID, нажмите **Сохранить и отправить тест в Telegram**.

✅ Вверху зелёная надпись «Тестовое сообщение отправлено», в Telegram пришло сообщение от бота.

**Почта.** На той же вкладке заполните SMTP-сервер, порт, шифрование, логин и пароль ящика, адрес отправителя и получателей. Нажмите **Сохранить и отправить тестовое письмо**.

✅ Зелёная надпись «Тестовое сообщение отправлено», письмо пришло (проверьте и папку «Спам»).

Токен и пароль после сохранения на странице не показываются. Чтобы их не менять, оставьте поле пустым.

## Часть 10. Zabbix и настенный экран (по желанию)

### Zabbix

Шаблон работает с Zabbix 7.0 и новее (проверен на 7.0 и 8.0). Zabbix делает один запрос в минуту и получает сразу всё: машины, задания и состояние самого сайта. Машины и задания он находит сам, раз в час.

**Шаг 20. Проверить, что Zabbix-сервер видит сайт.** На сервере Zabbix выполните (адрес сайта свой):

```bash
curl -s http://custos.lan/api/health
```

✅ Ответ `{"status":"ok","db":"ok","cron_lag_s":...}`. Если `"status":"fail"` и `cron_lag_s` больше 300 или `null`, не работает cron (шаг 12). Если ответа нет, Zabbix-сервер не видит сайт: проверьте DNS и сеть.

**Шаг 21. Импортировать шаблон.** На сайте: «Настройки» → вкладка «Zabbix и настенный экран». Нажмите ссылку `custos_template.yaml`, файл скачается. В Zabbix: **Сбор данных → Шаблоны** (Data collection → Templates), справа вверху **Импорт**, выберите файл, **Импорт**.

✅ В списке шаблонов появился `CUSTOS by HTTP`.

**Шаг 22. Создать узел.** **Сбор данных → Узлы сети → Создать узел сети** (Data collection → Hosts → Create host):

- Имя узла: `CUSTOS`
- Шаблоны: `CUSTOS by HTTP`
- Группы узлов: любая, например `Applications`
- Интерфейсы: не нужны

Вкладка **Макросы** (Macros), кнопка **Добавить** два раза:

| Макрос | Значение |
|---|---|
| `{$CUSTOS.URL}` | адрес сайта со страницы «Zabbix и настенный экран», без `/` в конце, например `http://custos.lan` |
| `{$CUSTOS.TOKEN}` | токен с той же страницы (кнопка «Скопировать»); тип значения — «Секретный текст» (Secret text) |

Нажмите **Добавить**.

**Шаг 23. Проверить.** Через 1–2 минуты откройте **Мониторинг → Последние данные** (Monitoring → Latest data), фильтр по узлу `CUSTOS`.

✅ «CUSTOS: health» = `ok`, «CUSTOS: machines» — число машин. Машины и задания появятся в течение часа. Чтобы не ждать: **Сбор данных → Узлы сети**, в строке `CUSTOS` ссылка **Обнаружение** (Discovery), отметьте оба правила и нажмите **Выполнить сейчас** (Execute now), через минуту обновите «Последние данные».

Что сообщает Zabbix:

| Триггер | Важность |
|---|---|
| «машина / задание: backup failed» — задание закончилось ошибкой | Высокая |
| «машина / задание: backup did not start on schedule» — пропуск, машина была включена | Средняя |
| «машина / задание: no recent successful copy» — давно нет успешной копии | Предупреждение |
| «машина / задание: storage will be full soon» — хранилище задания заполнится за 14 дней или раньше (как проблема «место» на сайте) | Предупреждение |
| «машина has been offline for more than 24h» (срок задаёт макрос `{$CUSTOS.OFFLINE.MAX}`) | Предупреждение |
| «monitoring site is unhealthy (database or cron)» | Высокая |
| «no data from the monitoring site for 10 minutes» | Высокая |

Код состояния задания (элемент «status code»): 0 — в норме, 1 — выполняется или на паузе, 2 — предупреждение или аномалия, 3 — пропуск, когда машина была выключена, 4 — давно нет успешной копии, 5 — пропуск, 6 — ошибка, 9 — отключено или ещё не запускалось. Если у задания несколько проблем, код показывает самую серьёзную. Пока идёт новый запуск, ошибка и пропуск остаются видны (код не меняется на 1).

### Настенный экран

**Шаг 24.** На той же вкладке скопируйте «Ссылку» настенного экрана и откройте её в браузере на телевизоре или мониторе (во весь экран: F11). Вход не нужен: доступ даёт токен в ссылке. Экран тёмный, сверху крупно проблемы, ниже плитки машин; обновляется сам каждые 30 секунд. Если связь с сервером пропала, вверху появится красная надпись «Нет связи с сервером».

Ссылку никому не публикуйте. Если она попала не туда, нажмите «Сгенерировать новый токен»: старая ссылка сразу перестанет работать, на экранах нужно будет открыть новую.

**Ограничить адреса.** В поле «Откуда можно» на той же вкладке перечислите адреса Zabbix-сервера и экранов (по одному в строке, можно подсети вида `192.0.2.0/24`) и нажмите «Сохранить». Пустое поле — с любых адресов. Это отдельный список: настенный экран не открывает сам сайт, а `/api/health` доступен всегда.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| `Permission denied` или `?php: No such file or directory` | Скрипт запущен без `php8.4`. Пишите `php8.4 bin/install.php`. |
| `PHP 8.3 or newer is required` | Запущено через `php`, а не через `php8.4`. |
| При входе на сайт «Форма устарела» | Сайт открыт по `http://`, а в `url` в `config.php` стоит `https://`, или пакет старше 06.11.2026. Исправьте `url` (шаг 10) или обновите пакет (раздел «Обновление»). |
| `config.php not found` | Не сделан шаг 9. |
| `Cannot connect to the database: ... Access denied` | В `config.php` имя базы, пользователь или пароль не совпадают с шагом 4. Исправьте (шаг 10) и запустите установку ещё раз. |
| `unzip: command not found` | Распакуйте архив в File Manager CloudPanel (правой кнопкой по файлу → Extract) и продолжайте с `cd server` в шаге 8. |
| Сайт показывает 404 или чужую страницу | Не сделан шаг 3: Root Directory должен быть `custos.lan/server/public`. |
| Браузер уходит на `https://` и ругается на сертификат | Не сделан шаг 5. |
| `custos.lan` не открывается вообще | Нет записи `custos.lan` в вашем локальном DNS, которая указывает на сервер. |
| В шаге 14 `custos.lan` не открывается с самого сервера | Под root добавьте в `/etc/hosts` строку `127.0.0.1 custos.lan`. |
| На «Главной» красная надпись «Фоновые задачи (cron) …» | Cron не работает: проверьте шаг 12. Вручную: `php8.4 bin/cron.php --verbose` в папке `server` — должен вывести блок `{ ... }` без ошибок. |
| Тест Telegram: `Telegram is not reachable` | Сервер не достучался до `api.telegram.org`. Если он закрыт у провайдера, укажите прокси в поле «Прокси», например `socks5h://192.0.2.1:1080`. |
| Тест Telegram: `HTTP 401` | Неверный токен: скопируйте его из сообщения `@BotFather` ещё раз. |
| Тест Telegram: `HTTP 400 Bad Request: chat not found` | Неверный Chat ID или бот не добавлен в группу (пункты 2–3 части 9). |
| Тест Telegram: `HTTP 403` | Бота удалили из группы или заблокировали в личном чате. Добавьте снова. |
| Тестовое письмо: `Could not connect to SMTP host`, `SMTP connect() failed` или `Could not authenticate` | Проверьте сервер, порт и шифрование (587 — STARTTLS, 465 — SSL), логин и пароль. Многие почтовые службы требуют «пароль приложения» вместо обычного. |
| На странице «Внутренняя ошибка сервера», в журнале `var/log` строка `Server key ... is missing` | Ключа сервера нет, например папку `server` удалили и распаковали заново. Выполните `php8.4 bin/install.php`: он создаст ключ. Если агенты уже были подключены, их придётся зарегистрировать заново. |
| Ошибка 500, или в логе `Permission denied` для папки `var` или `Server key ... cannot be read` | Файлы распакованы или установка запущена под root. Под root выполните `chown -R custos:custos /home/custos/htdocs/custos.lan` и проверьте снова. |
| Zabbix: элемент «CUSTOS: status data» не поддерживается, в ошибке `401` | Неверный макрос `{$CUSTOS.TOKEN}` (или токен сгенерирован заново). Скопируйте токен со страницы «Zabbix и настенный экран» ещё раз. |
| Zabbix: в ошибке `403` и `ip_not_allowed` | Адреса Zabbix-сервера нет в поле «Откуда можно». Добавьте его (адрес виден в ответе) или очистите поле. |
| Zabbix: в ошибке `Couldn't resolve host` или `Connection refused` | Zabbix-сервер не видит сайт: проверьте `{$CUSTOS.URL}` и шаг 20. |
| Настенный экран: «Ссылка устарела» | Токен сгенерирован заново. Откройте новую ссылку со страницы «Zabbix и настенный экран». |
| Настенный экран: «Доступ с адреса … запрещён настройками сайта» | Адреса экрана нет в поле «Откуда можно» (часть 10). |

Если ошибка другая, пришлите её текст целиком или скриншот.

## Обновление

**Старую папку `server` не удаляйте:** новый пакет распаковывается поверх неё. В ней лежат настройки и ключ сервера. Если ключ потерять, все подключённые агенты перестанут доверять серверу, и их придётся регистрировать заново.

1. Скачайте новый `custos-server.zip` (шаг 1) и загрузите его в папку `custos.lan` (шаг 6).
2. По SSH под пользователем сайта:
   ```bash
   cd ~/htdocs/custos.lan
   unzip -o custos-server.zip
   rm custos-server.zip
   php8.4 server/bin/migrate.php
   ```

✅ Последняя команда выводит `[ok] Database schema is up to date` или `[ok] Applied N migration(s)`.

После обновления откройте «Главную»: внизу страницы видна новая версия. Если в блоке «Требует внимания» красная надпись про cron, проверьте шаг 12 — начиная с версии 0.2.0 без cron не проверяются пропуски и не отправляются уведомления.

Настройки (`config/config.php`), ключи сервера (`config/keys/`) и папка `var/` в пакет не входят, поэтому распаковка поверх их не трогает.

**Версия 0.3.0 (управление).** `migrate.php` применит миграцию `003`. Новое:
- раздел «Обновления»: сервер раз в сутки обращается к `api.github.com`, чтобы узнать новую версию 7-Zip. Если у сервера нет выхода в интернет, выключите проверку на той же странице, а установщик 7-Zip загружайте вручную;
- загруженные пакеты обновления и установщики 7-Zip лежат в `server/var/packages/`;
- пакет обновления CUSTOS загружается через сайт. Если он больше лимита PHP, сайт напишет об этом; лимит поднимается в CloudPanel: сайт → **Settings** → **PHP Settings**, `upload_max_filesize` и `post_max_size`, например `100M`.

**Версия 0.4.0 (аналитика и интеграции).** `migrate.php` применит миграции `004` и `005` и создаст два токена (строки `[ok] Generated zabbix_token ...` и `[ok] Generated wall_token ...`). Новое:
- на «Главной» тепловая карта результатов за 30 дней, на странице задания графики, на странице машины блок «Хранилища» с прогнозом заполнения;
- предупреждение о заполнении хранилища: когда по прогнозу место закончится за 14 дней или раньше, на «Главной» появляется проблема «место» и приходит одно сообщение. Порог (или 0, чтобы выключить) — «Настройки» → «Пороги»;
- в «Запусках» кнопка «Скачать CSV» (для Excel);
- Zabbix и настенный экран (часть 10);
- профиль пользователя: щёлкните свой логин справа вверху — язык, тема, смена пароля. Язык по умолчанию для всех задаётся в «Настройки» → «Общие»;
- значок сайта во вкладке браузера.

Ничего настраивать не нужно. Если сайт работает без CloudPanel, проверьте блок nginx: файлы `favicon.ico`, `favicon.svg` и `assets/vendor/chart.umd.min.js` должны отдаваться из `server/public`, как остальные файлы (с примером из раздела «Без CloudPanel» так и есть).

**Версия 0.4.1.** Миграций нет. Новый порог предупреждения о месте действует сразу после сохранения настроек, а не через час. На длинных страницах справа внизу появляется кнопка «Наверх».

**Версия 0.4.2.** `migrate.php` применит миграции `006` и `007`: интервал heartbeat по умолчанию теперь 20 секунд вместо 60, а машина считается «не на связи» через 15 минут вместо 60. Если на сайте стояли прежние значения 60, миграции меняют их; числа, выставленные вручную, остаются. Ещё в этой версии:
- в редакторе заданий и шаблонов кнопки «Создать задание» и «Сохранить» снова отправляют форму (раньше молча не отправляли, если расписание не «по таймеру»);
- «Настройки» → «Общие»: строка подключения — адрес сервера и код регистрации одной строкой для программы на машине; подсказки у интервала heartbeat и у «не на связи»;
- отключённая машина связывается с сайтом раз в 5 минут, поэтому после включения возвращается быстрее (нужен клиент с этой правкой);
- пример пути в источниках и назначениях меняется вместе с типом;
- «Заменить пароль» выглядит как ссылка. У SSH-ключа и облачных дисков пароль на сайте не меняется: они создаются на машине.

**Версия 0.4.3.** Миграций нет. В «Настройки» → «Общие» осталась одна строка подключения: в ней и адрес сервера, и код регистрации. Отдельных полей «Адрес сервера» и «Код регистрации» больше нет. `bin/install.php` в конце тоже печатает строку подключения, а имитатор принимает её в `--connect='...'`. Если обновлять нечего (на машинах уже эта версия или новее), сайт так и пишет, обычным сообщением, а не красным.

**Версия 0.4.4.** Миграций нет. Редактор заданий и шаблонов знает облачные диски (Google Диск, Яндекс Диск, Dropbox; этап 4б клиента). Аккаунт облачного диска подключается только в CUSTOS на самой машине, через браузер; на сайте выбирается уже подключённый, нового здесь не создать. 7z и зеркало для облачного диска недоступны, архив можно писать частями («Размер части, МБ»). Шаблон аккаунт не хранит: при применении на каждой машине берётся аккаунт этого сервиса, подключённый на ней; если его нет или их несколько, сайт об этом скажет.

## Что сохранять в резервной копии

- базу `custos`;
- `server/config/config.php`;
- `server/config/keys/` — ключ сервера. Если он потеряется, все агенты перестанут доверять серверу, и их придётся регистрировать заново.
- `server/var/packages/` — по желанию: пакеты обновления можно загрузить заново.

## Без CloudPanel

Пример для Ubuntu 24.04 (PHP 8.3, MariaDB, nginx). На других системах нужны те же части: PHP 8.3 или новее с PHP-FPM и расширениями `pdo_mysql`, `curl`, `mbstring`, `openssl`, `zlib`; MariaDB 10.11+ или MySQL 8.0+; nginx. В Debian 12 PHP 8.2, этого мало: поставьте PHP 8.4 из репозитория packages.sury.org и везде пишите `php8.4`.

Все команды этого раздела, кроме отмеченных, выполняются **под root**. Сайт работает от отдельного пользователя `custos`, как в CloudPanel.

**Шаг Н1. Пакеты.**

```bash
apt update
apt install -y nginx mariadb-server php8.3-fpm php8.3-cli php8.3-mysql php8.3-curl php8.3-mbstring unzip
```

**Шаг Н2. Пользователь и папка сайта.**

```bash
adduser --disabled-password --gecos "" custos
mkdir -p /var/www/custos
chown custos:custos /var/www/custos
```

**Шаг Н3. База данных.** Вместо `ПАРОЛЬ` придумайте свой пароль и запишите его:

```bash
mariadb -e "CREATE DATABASE custos CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; CREATE USER 'custos'@'localhost' IDENTIFIED BY 'ПАРОЛЬ'; GRANT ALL ON custos.* TO 'custos'@'localhost';"
```

**Шаг Н4. PHP-FPM от пользователя сайта.** Создайте файл:

```bash
nano /etc/php/8.3/fpm/pool.d/custos.conf
```

с таким содержимым:

```ini
[custos]
user = custos
group = custos
listen = /run/php/php8.3-fpm-custos.sock
listen.owner = www-data
listen.group = www-data
pm = ondemand
pm.max_children = 10
php_admin_value[upload_max_filesize] = 100M
php_admin_value[post_max_size] = 100M
```

```bash
systemctl restart php8.3-fpm
```

**Шаг Н5. nginx.**

```bash
nano /etc/nginx/sites-available/custos
```

```nginx
server {
    listen 80;
    server_name custos.lan;
    root /var/www/custos/server/public;
    index index.php;
    client_max_body_size 100m;   # агентам хватает 10m; больше нужно для загрузки пакетов обновления через сайт

    location / {
        try_files $uri /index.php?$query_string;
    }

    location = /index.php {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass unix:/run/php/php8.3-fpm-custos.sock;
    }

    location ~ \.php$ {
        return 404;
    }
}
```

```bash
ln -s /etc/nginx/sites-available/custos /etc/nginx/sites-enabled/custos
nginx -t
systemctl reload nginx
```

✅ `nginx -t` пишет `syntax is ok` и `test is successful`.

**Шаг Н6. Пакет и установка.** Скачайте `custos-server.zip` (шаг 1) и загрузите его в `/home/custos/` (WinSCP, протокол SFTP; или `scp custos-server.zip root@адрес-сервера:/home/custos/`). Дальше **под пользователем сайта**:

```bash
chown custos:custos /home/custos/custos-server.zip
su - custos
cd /var/www/custos
unzip -o ~/custos-server.zip
rm ~/custos-server.zip
cd server
cp config/config.example.php config/config.php
nano config/config.php
```

В `config.php` заполните то же, что в шаге 10 (база `custos`, пользователь `custos`, пароль из шага Н3, адрес сайта, часовой пояс). Затем:

```bash
php8.3 bin/install.php
exit
```

✅ Вывод как в шаге 11, все строки начинаются с `[ok]`.

**Шаг Н7. Cron** (под root):

```bash
echo '* * * * * custos /usr/bin/php8.3 /var/www/custos/server/bin/cron.php' > /etc/cron.d/custos
```

Дальше проверьте сайт и агента, как в частях 6 и 7 (шаги 13–17), только пишите `php8.3` вместо `php8.4`, а папка сайта — `/var/www/custos/server`. Обновление: распакуйте новый пакет поверх в `/var/www/custos` под пользователем `custos` и выполните `php8.3 server/bin/migrate.php`.

**HTTPS (по желанию).** Если у сайта есть публичное имя: `apt install -y certbot python3-certbot-nginx`, затем `certbot --nginx -d ваш.домен`. В `config.php` поменяйте `url` на `https://...`.

Если сайт стоит в подпапке или за обратным прокси, часть пути, начиная с `/api/v1/`, должна доходить до PHP без изменений: по ней проверяются подписи агентов. Адреса прокси перечислите в `trusted_proxies` в `config.php`.
